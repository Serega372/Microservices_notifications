# API Gateway и сервис авторизации / аутентификации

## Описание

Начинать прочтение рекомендуется с данного репозитория.
Данный репозиторий содержит инфраструктурные и сервисные компоненты, отвечающие за:
- маршрутизацию HTTP-запросов,
- централизованную проверку авторизации,

- репозиторием микросервисов уведомлений,

## Состав репозитория

### 1. API Gateway (Traefik)

Используется **Traefik** в роли обратного прокси и API Gateway.

Функции:
- маршрутизация запросов к микросервисам `notifications-gateway`;
- централизованная проверка авторизации;
- отказоустойчивость за счёт балансировки нагрузки и ограничения запросов;
- интеграция с сервисом авторизации через middleware.

#### Проверка авторизации

Каждый защищённый запрос проверяется Traefik через обращение к эндпоинту: 

POST `auth/verify`
Сервис авторизации возвращает:
- `200 OK` — запрос валиден;
- `401 Unauthorized` — запрос отклонён.

---

### 2. Сервис авторизации и аутентификации

Отдельный микросервис, отвечающий за:
- регистрацию пользователей;
- вход в систему;
- обновление токенов;
- проверку валидности access-токенов.

Токен живет 5 минут, рефреш токен живет 60 минут

#### Основные эндпоинты

| Метод | Эндпоинт              | Описание                                                                                 |
|-------|-----------------------|------------------------------------------------------------------------------------------|
| POST  | `/auth/register`      | Регистрация пользователя                                                                 |
| POST  | `admin/auth/register` | Регистрация пользователя как админ, с возможностью указания роли для нового пользователя |
| POST  | `/auth/login`         | Аутентификация                                                                           |
| POST  | `/auth/refresh`       | Обновление токена                                                                        |
| GET   | `auth/verify`         | Проверка валидности запроса (используется Traefik)                                       |

Проект развернут на сервере и доступен для демонстрации и проверки.
Для демонстрации, предоставляется read-only доступ к базам данных:
- `названия баз: messages_db, notifications_db, auth_db`
  - `юзер: demonstration`
  - `пароль: 2345g4rofi3pfjpfer33gf`
  - `хост: http://85.234.22.232`
  - `порты: messages_db - 9050, notifications_db - 7050, auth_db - 6050`
#### Базовые url:
- `http://85.234.22.232:5000`
- `https://monolit-is-bad.yegress.netcraze.pro`

#### Доступные эндпоинты:
- POST `/auth/register`
  - ```
    JSON:
    {
      "username": "...",
      "password": "..."
    }
    ```
- POST `/admin/auth/register`
  - ```
    На данный момент есть две роли. Admin = 0, User = 1
    JSON:
    {
      "username": "...",
      "password": "...",
      "userRole": int
    }
    ```
- POST `/auth/login`
  - ```
    JSON:
    {
      "username": "...",
      "password": "..."
    }
    ```
- POST `/auth/refresh`
  - ```
    JSON:
    {
      "token": "Guid"
    }
    ```
- GET `/auth/verify`
- POST `/notifications/send`
  - ```
    Для всех каналов отправки обязательные поля "sender" и "recipients", 
    остальные поля внутри "payload" являются необязательными
    JSON:
    Email:
    {
      "type": "email",
      "payload": {
        "sender": "...",
        "recipients": ["...", "...", ...],
        "subject": "...",
        "body": "...",
        "attachments": ["...", "...", ...]
      }
    }
    
    Sms:
    {
      "type": "sms",
      "payload": {
        "sender": "...",
        "recipients": ["...", "...", ...],
        "body": "...",
      }
    }
    
    Push:
    {
      "type": "push",
      "payload": {
        "sender": "...",
        "recipients": ["...", "...", ...],
        "title": "...",
        "body": "...",
        "attachments": ["...", "...", ...]
      }
    }
    ```
#### Примечания 
- Все запросы, кроме `/auth/*`, проходят проверку токена через API Gateway (Traefik)
- Для работы с `notifications/send` требуется JWT-токен, который можно получить выполнив аутентификацию, он сохраняется в куки, и далее засунуть его в куки `someInformation`:
```
someInformation=токен; Path=/; Secure;
```

### Базы данных
Используется PostgreSQL. Сервис авторизации использует собственную БД для:
- хранения пользователей;
- refresh-токенов;

### Безопасность

- Все запросы проходят через API Gateway. 
- Прямой доступ к микросервисам извне отсутствует.
- Используется централизованная проверка токенов. 
- Базы данных могут быть доступны в режиме read-only для демонстрации. 

### Назначение репозитория
Репозиторий предназначен для:
- демонстрации работы API Gateway;
- демонстрации централизованной авторизации;
- анализа микросервисной архитектуры.
